# Phase 20 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | Tailwind CSS 3 with Mystic UI setup and repo-local dark-primary CSS classes; shadcn is not applicable for this SolidStart stack. |
| Preset | `withMysticUI`, Tailwind `darkMode: "selector"`, `.dark` active on the root document. |
| Component library | Mystic UI dependency plus repo-local `SiteLayout`, `ReactiveSurface`, and CSS component classes. Do not add new UI dependencies. |
| Icon library | None for Phase 20. Use text links and existing button/link classes; do not add an icon package for these routes. |
| Font | `Inter, ui-sans-serif, system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif`. |

---

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Tight text/icon gaps, small metadata spacing. |
| sm | 8px | Chip gaps, compact row gaps, card sub-section spacing. |
| md | 16px | Default grid gaps, card internal stacks, inline control spacing. |
| lg | 24px | Card padding, notice/panel padding, route section internal padding. |
| xl | 32px | Detail page layout gaps, intro-to-content rhythm, major card groups. |
| 2xl | 48px | Mobile page vertical padding and major section breaks. |
| 3xl | 64px | Desktop page vertical padding and sticky-header scroll offsets. |

Exceptions: interactive anchors and buttons must keep the existing `min-h-11` 44px target size. Cards stay at 8px radius, chips and pills stay at 6px radius. Route-specific CSS may only add multiples of 4 unless matching these existing radii or the 44px target.

---

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label | 14px | 600 | 1.4 |
| Heading | 20px | 600 | 1.25 |
| Display | 36px | 600 | 1.15 |

Use only weights 400 and 600. Keep letter spacing normal. Long theme titles, proof points, chips, and links must wrap with `overflow-wrap: anywhere` through existing surface/card classes.

---

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#050608` with existing shell gradient through `#0d1117` and `#12100b` | Page background, dark root, main shell. |
| Secondary (30%) | `rgba(24, 24, 27, 0.84)` over `#0d1117` | Cards, panels, sticky nav, visual surfaces, empty states. |
| Accent (10%) | `#6ee7b7` emerald, with `#67e8f9` cyan only for focus/hover support | Primary route actions, text links, focus rings, active borders, tier pills, small relationship-count accents. |
| Destructive | Not used | Phase 20 has no destructive actions. Do not introduce destructive UI. |

Accent reserved for: `Explore theme` links, `Browse theme paths` fallback action, `Back to themes` text link, focused link/button rings, hover borders on theme/project/writing cards, `tier-pill` relationship count/status accents. Do not use accent as a broad background wash, decorative orb, or all-purpose section color.

## Route Interaction Contract

| Surface | Contract |
|---------|----------|
| `/themes` index | Render public theme entries from `publicThemeEntries()` as a responsive card grid. Each card must show title, summary, audience, small helper-derived relationship counts or labels, and an `Explore theme` link built with `themeDetailPath()`. |
| Theme detail page | Gate with `maybePublicThemeEntryBySlug()`. Render one H1, the theme summary as the main idea, audience, proof points, and related project/writing cards resolved through Phase 19 helpers. |
| Related cards | Related projects and writing must use existing display records from `relatedProjectDetailPageProjectsForTheme()` and `relatedWritingEntriesForTheme()`. Do not duplicate project or writing descriptions inside route components. |
| Fallback state | Unknown, hidden, draft, unsupported, archived, or invalid slugs all get the same generic fallback. Do not echo the raw slug, status, private fields, or non-public theme content. |
| Links and keyboard | Use real anchors with descriptive text. Do not make the whole card a click trap. Every interactive element keeps the existing 44px minimum target and visible cyan focus ring. |
| Motion | `ReactiveSurface` may wrap grids where existing routes already do this. Do not add motion libraries. Hover and pointer effects must remain disabled by existing reduced-motion, coarse-pointer, and mobile guards. |
| Responsive layout | Use existing `theme-card`, `project-anchor-card`, `surface-card`, `label-row`, `chip`, `tier-pill`, `link-list`, `writing-related-grid`, and route grid patterns before adding CSS. Any new grid must use `repeat(auto-fit, minmax(min(100%, 20rem), 1fr))` or the closest existing pattern. |

## Phase Boundaries

| Boundary | Contract |
|----------|----------|
| In scope | `/themes`, public `/themes/{slug}` pages, navigation route entry if needed, explicit prerender route inclusion, non-leaking fallback, dark responsive UI. |
| Out of scope | Phase 21 collaboration panels and project/writing theme cross-links; Phase 22 route-specific metadata, JSON-LD, sitemap, and social previews; Phase 23 release evidence labels and browser-suite expansion. |
| OpenLinks | Preserve existing footer/profile/contact discoverability only. Do not make OpenLinks the theme primary CTA. |
| Registry | Use checked-in theme/project/writing helpers only. No CMS, MDX, runtime fetches, search/filter UI, live external link checks, or new external content sources. |

## Verification Contract

| Check | Required Evidence |
|-------|-------------------|
| Static routes | `/themes` and every `themeDetailRoutes()` value are included in `prerenderRoutes` while non-public theme records are excluded. |
| Generated HTML | Static output for `/themes` and public theme details contains expected titles, summaries, audience copy, proof points, related project links, related writing links, and footer OpenLinks text before hydration. |
| Fallback safety | A focused test proves an unknown/non-public slug renders the generic fallback and does not include the requested slug or private theme content. |
| Dark responsive UI | Desktop and mobile dark rendering must have no horizontal overflow, obvious text overlap, or missing `.dark` root. |
| Accessibility | New routes keep semantic headings, axe-clean output, visible keyboard focus, and descriptive link text. |
| Reduced motion | If `ReactiveSurface` is used on theme routes, existing reduced-motion/coarse-pointer/mobile behavior must keep hover/pointer decoration inert. |
