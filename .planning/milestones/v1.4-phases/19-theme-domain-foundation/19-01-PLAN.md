<threat_model>
## Trust Boundaries

| Boundary | Description |
| --- | --- |
| Maintainer-authored theme data -> public theme helpers | Checked-in records become future public route inputs only through `publicThemeEntries()` and `themeDetailRoutes()`. |
| Theme related slugs -> project and writing registries | Theme records reference existing project and writing records by slug, then helpers resolve public display records from authoritative registries. |
| Domain validation -> curation CLI | Pure validation output crosses into a process-exiting developer command used by local and aggregate verification. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
| --- | --- | --- | --- | --- |
| T-19-01 | Information Disclosure | `publicThemeEntries()` and `themeDetailRoutes()` | mitigate | Derive both public entries and route strings from `status: "public"` only; tests must prove draft, hidden, unsupported, and archived records are excluded. |
| T-19-02 | Tampering | `validateThemeRegistry()` | mitigate | Validate slug format, duplicate slugs, duplicate display orders, unsupported status values, and required field presence before curation passes. |
| T-19-03 | Information Disclosure | `relatedProjectDetailPageProjectsForTheme()` and `relatedWritingEntriesForTheme()` | mitigate | Resolve relationships through `maybeProjectDetailPageProjectBySlug()` and `maybePublicWritingEntryBySlug()`; validators reject unresolved selected-project and public-writing relations. |
| T-19-04 | Tampering | Theme copy fields | mitigate | Keep theme copy as typed plain strings and do not introduce Markdown, MDX, raw HTML, parser pipelines, CMS data, or runtime fetches in Phase 19. |
| T-19-05 | Repudiation | `scripts/verify-curation.ts` | mitigate | Emit stable `theme/{slug}` prefixed warning/error lines with issue codes so maintainers can trace failures to exact records. |
</threat_model>
