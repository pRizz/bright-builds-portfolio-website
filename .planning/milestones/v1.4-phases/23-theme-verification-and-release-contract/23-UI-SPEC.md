# Phase 23 - UI Design Contract

> Visual and interaction contract for a release verification phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | Tailwind CSS 3 with Mystic UI setup and repo-local dark-primary CSS classes; shadcn is not applicable for this SolidStart stack. |
| Preset | `withMysticUI`, Tailwind `darkMode: "selector"`, `.dark` active on the root document. |
| Component library | Existing Mystic UI dependency plus repo-local `SiteLayout`, `ReactiveSurface`, and CSS component classes. Do not add UI dependencies or new component families in Phase 23. |
| Icon library | None for Phase 23. Do not add icons for release evidence, docs, labels, or browser checks. |
| Font | `Inter, ui-sans-serif, system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif`. |

Design system contract:

- Phase 23 verifies existing theme route UI. It must not introduce new theme routes, hero designs, cards, panels, navigation entries, CTAs, or product scope.
- Existing `/themes`, public `/themes/{slug}`, project detail, writing detail, footer, and contact/profile identity surfaces remain visually authoritative.
- Browser verification must preserve the dark-primary default, root `.dark` class, readable contrast, stable wrapping, and desktop/mobile no-overlap behavior already required by `AGENTS.md`.
- Use existing release/static/browser verification surfaces. Do not add screenshot baselines, image generation, live link crawling, shadcn blocks, third-party registries, or new motion libraries.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Existing tight metadata and action-label gaps only. |
| sm | 8px | Existing chip gaps, compact rows, and link-list gaps only. |
| md | 16px | Existing default grid gaps, panel stacks, and route content rhythm only. |
| lg | 24px | Existing card and panel padding only. |
| xl | 32px | Existing detail layout gaps and major content group rhythm only. |
| 2xl | 48px | Existing mobile page vertical spacing and major section breaks only. |
| 3xl | 64px | Existing desktop page spacing and sticky-header scroll offsets only. |

Exceptions: interactive anchors and buttons keep the existing `min-h-11` 44px target. Cards and panels keep 8px radius; chips and pills keep 6px radius. Phase 23 should not introduce new spacing, radius, layout, or target-size rules.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label | 14px | 600 | 1.4 |
| Heading | 20px | 600 | 1.25 |
| Display | 36px | 600 | 1.15 |

Typography rules:

- Use only weights 400 and 600.
- Keep letter spacing normal and do not scale type with viewport width.
- Phase 23 must not change the typography scale. Verification should prove existing theme titles, summaries, proof points, project names, writing titles, URLs, and action labels wrap without overlap.
- Long route text must continue to rely on existing `min-width: 0`, `text-balance`, and `overflow-wrap: anywhere` patterns.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | No new CTA. Existing theme cards retain `Explore theme`; the existing generic fallback retains `Browse theme paths`. |
| Empty state heading | Existing `/themes` empty state remains `No public themes yet`. |
| Empty state body | Existing `/themes` empty body remains `Theme paths will appear here after public theme records are added to the curated theme registry.` |
| Error state | Existing fallback remains `No public theme here. Browse theme paths to find a public route through Peter's work.` Do not echo the requested slug. |
| Destructive confirmation | None: Phase 23 has no destructive actions. |

Release evidence wording:

| Surface | Required Wording |
|---------|------------------|
| Aggregate clean-builder command | `bun run install:browser && bun run verify` |
| Theme automated evidence label | `theme route coverage` |
| Theme static coverage fact | `theme metadata, JSON-LD, sitemap, related project links, related writing links, collaboration links, and forbidden runtime residue coverage` |
| Theme browser coverage fact | `theme axe, desktop/mobile dark layout, representative keyboard, and representative reduced-motion coverage` |
| Representative smoke route | Derive from `themeDetailRoutes()[0]`; do not hard-code a public theme slug in release helper code. |

Forbidden evidence claims:

- Do not claim complete WCAG certification, visual-regression baselines, screenshot approval, hosted Lighthouse audits, preview-deployment verification, post-deploy verification, manual review, live external-link reachability, or external network checks as automated evidence.
- Manual external-link smoke checks, preview deployment checks, post-deploy checks, and hosted audits may remain checklist prose only.
- OpenLinks wording stays low-intrusion: `OpenLinks profile`, `Contact path`, or existing external-link policy coverage. Do not promote OpenLinks as a primary theme CTA or claim live reachability.

## Browser Verification Contract

| Check | Contract |
|-------|----------|
| Route coverage | Axe and layout checks must derive from `prerenderRoutes`, covering `/themes` and every public `themeDetailRoutes()` value without copied slug lists. |
| Axe | Every `prerenderRoutes` route must have no automated axe violations in Playwright. Evidence must describe this as automated axe coverage, not full accessibility certification. |
| Desktop dark layout | `chromium-desktop` at `1440x1000` must prove `.dark` is present, no horizontal overflow exists, and visible header/footer/main text and controls do not obviously overlap. |
| Mobile dark layout | `chromium-mobile` using the Pixel 7 project must prove the same dark root, overflow, and overlap contract. |
| Keyboard reachability | Representative checks must reach home navigation, theme navigation, a public theme detail route, the theme index back-link, related project route, related writing route, reciprocal project/writing theme links, and an external theme collaboration action. |
| Reduced motion | `chromium-reduced-motion` must prove existing decorative hover/pointer motion is inert on `/`, a representative project detail route, a representative writing detail route, `/themes`, and a representative theme detail route. |
| Touch/coarse pointer | Existing CSS guards for `prefers-reduced-motion`, coarse pointer, and max-width `640px` must keep reactive hover decoration and transform motion disabled. |
| Text wrapping | Desktop and mobile checks must treat horizontal overflow, obvious text overlap, clipped focus targets, and missing root dark class as release blockers. |

Do not add screenshot baselines or an exhaustive per-theme interaction matrix in Phase 23 unless existing route-derived checks cannot prove a required Phase 23 route path.

## Static And Release Verification Contract

| Check | Required Evidence |
|-------|-------------------|
| Static theme parity | Generated HTML checks derive `/themes` and all public `/themes/{slug}` routes from helpers, not copied route lists. |
| Visible content | Static checks prove theme titles, summaries, audience copy, proof points, related selected-project links, related public-writing links, collaboration action links, fallback copy, and footer OpenLinks text before hydration. |
| Metadata and JSON-LD | Static checks prove route-specific theme metadata, theme index `ItemList` JSON-LD, theme detail `CollectionPage` JSON-LD, canonical URLs, Open Graph/Twitter metadata, and checked-in social fallback usage. |
| Sitemap inclusion/exclusion | Static checks prove `/themes` and public theme details appear in sitemap output while unknown, hidden, draft, unsupported, archived, and otherwise non-public theme paths stay excluded. |
| Forbidden residue | Static/release checks fail on runtime GitHub/API/token residue, unsafe generated links, sensitive query keys, and fallback leakage of non-public theme slugs or content. |
| Release-readiness document | `docs/release-readiness.md` must be enforced by code-owned facts for theme route coverage, theme static coverage, theme browser coverage, and a helper-derived representative theme smoke route. |
| Aggregate gate | `bun run verify` must remain non-mutating and end with `bun run verify:release` after format, check, typecheck, tests, curation, runtime-GitHub, helper-surface, visual-system, build, browser, and static verification. |
| Final proof | Phase execution must report the exact `bun run install:browser && bun run verify` result, or state clearly when browser installation was already satisfied locally. |

| In Scope | Out of Scope |
