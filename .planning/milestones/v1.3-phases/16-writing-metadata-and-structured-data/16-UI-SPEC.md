# Phase 16 - UI Design Contract

> Visual and interaction contract for Writing Metadata and Structured Data. Generated by gsd-ui-researcher, pending verification by gsd-ui-checker.

---

## Scope Locks

Phase 16 is metadata and discovery work for the writing routes that Phase 15 already made visible. It must preserve the existing dark-primary writing index, writing detail pages, unknown-writing fallback, navigation, footer, and related project panels without adding new user-facing layout scope.

In scope:

- Add route-specific head metadata for `/writing` and every public `/writing/{slug}` route.
- Add static writing JSON-LD before hydration through Solid route heads.
- Keep sitemap behavior route-derived through `prerenderRoutes`, `writingDetailRoutes()`, and `sitemapXml()`.
- Reuse the checked-in static social preview fallback at `/social/bright-builds-og.png`.
- Reuse existing route-visible copy from Phase 15 unless a metadata-only title or description needs helper-derived text.

Out of scope:

- No new visible writing cards, panels, badges, banners, modals, social-preview UI, or sharing widgets.
- No new primary navigation item, header/footer OpenLinks placement, writing CTA, RSS/search/tag archive UI, newsletter capture, comments, CMS/admin, MDX, runtime content fetching, dynamic Open Graph image route, or server endpoint.
- No Phase 17 release-evidence labels, release-readiness docs, broad browser gate expansion, or aggregate release-contract wording.

## Route-Visible Non-Regression Contract

### `/writing` Index

- Preserve the Phase 15 first viewport and visible route copy:
  - eyebrow: `Notes and essays`
  - H1: `Writing`
  - lead: `Curated notes on agentic engineering, open systems, identity, and practical web software.`
- Keep writing entries rendered from `publicWritingEntries()` in helper-provided order.
- Keep visible card content unchanged: title, summary, kind, date when available, topics/tags, related project count, and `Read note` or `Read essay`.
- Add writing index JSON-LD in the document head/body script area only; it must not render as visible page text.

### `/writing/{slug}` Detail

- Preserve the Phase 15 article surface: back link, kind eyebrow, H1 title, lead summary, metadata chips, body sections, callouts, and related project cards.
- Detail head metadata must derive from the selected public entry:
  - title pattern: `{entry.title} | Writing | Bright Builds`
  - description: `entry.summary`
  - canonical: `${peterProfile.canonicalOrigin}${writingDetailPath(entry)}`
  - Open Graph image: checked-in fallback social image
  - Twitter card: `summary_large_image`
- Article-flavored social metadata is head-only: `og:type="article"`, published/modified time when available, and topics/tags where supported.
- `BlogPosting` JSON-LD is non-visual and must not create a visible publisher badge, author card, tag cloud, or body duplicate.

### Unknown Writing Slug

- Preserve the non-leaking fallback:
  - title: `No public writing here | Writing | Bright Builds`
  - description/error copy: `Return to the writing index to browse published notes.`
  - visible CTA: `Browse writing`
- Do not show requested slugs, draft titles, hidden titles, archived-only titles, or private content.
- Unknown-route metadata should help users and crawlers recover without implying that unpublished content exists.

### Sitemap And Social Fallback

- Sitemap behavior is not a visible route UI.
- Public writing detail routes enter sitemap output only through `writingDetailRoutes()` and `prerenderRoutes`.
- Draft, hidden, archived-only, unpublished, unknown, and unsupported writing paths must stay excluded.
- The existing `/social/bright-builds-og.png` fallback is the only social image behavior in this phase. Do not add route-visible image preview cards or dynamic image endpoints.

## Interaction Contract

- No new route-visible controls, toggles, filters, menus, share buttons, copy buttons, tabs, forms, or destructive actions are allowed.
- Existing links remain the only interactive elements on writing pages.
- The primary nav `Writing`, writing card links, `Back to writing`, related project links, footer OpenLinks link, and fallback `Browse writing` CTA must remain keyboard reachable.
- Focus styling must remain the existing cyan `focus-visible` ring.
- Existing `ReactiveSurface` behavior may remain on writing card grids, but metadata work must not add new animation or pointer effects.
- Reduced-motion, coarse-pointer, and mobile guards in `src/styles/app.css` must remain effective.
- Head metadata, JSON-LD, canonical links, asset links, and sitemap changes must not shift layout, alter scroll position, steal focus, or affect tab order.

- Metadata descriptions should be concise and derived from trusted route/profile/writing helpers, not duplicated route-component literals.
- Link labels must stay destination-specific and unchanged from Phase 15.

- The Bright Builds/Peter Ryszkiewicz portfolio brand remains primary on writing routes.

## Verification Contract

Phase 16 verification should prove metadata behavior without expanding Phase 17 release-evidence scope.

Implementation must prove:

- `/writing` renders route-specific title, description, canonical URL, Open Graph, Twitter metadata, asset links, and writing index `ItemList` JSON-LD before hydration.
- Every public `/writing/{slug}` route renders entry-specific title, description, canonical URL, article-flavored Open Graph metadata, Twitter metadata, and `BlogPosting` JSON-LD before hydration.
- The existing static social image fallback is used for index and detail metadata.
- Generated sitemap output includes `/writing` and every public writing detail route, and excludes draft, hidden, archived-only, unpublished, unknown, and unsupported writing paths.
- Route-visible content, layout, dark palette, typography, focus styles, reduced-motion behavior, and tab order do not regress from Phase 15.
- OpenLinks remains subtle: existing footer link plus `Person.sameAs` reuse only.

Recommended commands for executor verification:

- `bun run format:check`
- `bun run check`
- `bun run typecheck`
- `bun run test`
- `bun run build`
- `bun run generate:static-metadata`
- `bun run verify:static` only if implementation adds or updates narrow static assertions needed to prove Phase 16 behavior

Do not add Phase 17 release-readiness labels, broad browser coverage claims, or aggregate evidence wording in this phase.
