    Create `scripts/generate-social-previews.ts` as the thin Bun/TypeScript imperative shell required by D-01.     Implement argument parsing with exactly one supported flag: `--check`. Any other argument prints `Usage: bun run scripts/generate-social-previews.ts [--check]` and exits `1`.

    At the start of both modes:
    - call `const targets = socialPreviewTargets();`
    - call `const validationFindings = validateSocialPreviewTargets(targets);`
    - if validation findings exist, map them into `target-validation` check findings, print one `[social previews error] target-validation ${routePath}: ${message}` line per finding, and exit `1` before rendering, writing, or cleanup per D-16.

    Generate mode must:
    - render every target with `renderSocialPreviewTarget(target)`;
    - create directories for each generated PNG with `mkdirSync(dirname(filePath), { recursive: true })`;
    - write a PNG only when the target file is missing or its bytes differ from rendered bytes;
    - scan managed PNGs with `managedSocialPreviewPngFiles()` and remove only files whose asset paths are absent from the current target set;
    - never remove or write `public/social/bright-builds-og.png`, `public/favicon.svg`, `public/icon-192.png`, `public/apple-touch-icon.png`, `public/sitemap.xml`, `public/robots.txt`, or any path outside `public/social/generated/`;
    - write `public/social/generated/manifest.json` using `socialPreviewManifestForRenderedPreviews(rendered)` and `serializeSocialPreviewManifest(manifest)`;
    - print `Generated 13 social preview PNGs and public/social/generated/manifest.json`.

    Check mode must:
    - be read-only and never call `writeFileSync`, `mkdirSync`, or `rmSync`;
    - render every target twice with the same render helper;
    - compute actual file metadata for each expected PNG: existence, byte size, SHA-256, dimensions from PNG IHDR offsets 16 and 20, and file path;
    - read and parse `public/social/generated/manifest.json`; if missing or invalid, report `manifest-drift`;
    - compare actual file checksum to first-render SHA-256 for `checksum-drift`;
    - compare manifest entry `sourceFingerprint` to target `sourceFingerprint` for `stale-fingerprint`;
    - compare actual file dimensions to `1200x630` for `wrong-dimensions`;
    - compare actual byte size to `maxSocialPreviewPngBytes` for `oversized-file`;
    - call `isBlankRenderedImage(firstRender.pixels)` for `blank-image`;
    - compare first and second render hashes for `nondeterministic-render`;
    - find orphan managed PNGs under `public/social/generated/` not represented by current target asset paths;
    - pass all inputs into `socialPreviewCheckFindings()` and print each finding as `[social previews error] ${code} ${routePath ?? "-"} ${assetPath ?? "-"}: ${message}`;
    - exit `1` if any finding exists, otherwise print `Verified 13 deterministic social preview PNGs and manifest entries.`

    Do not add a copied route array, hand-authored route-to-image map, metadata wiring to `src/domain/seo.ts`, JSON-LD image changes, freshness reports, release docs, release evidence labels, static verifier changes, browser tests, runtime endpoints, API routes, or visitor UI.

<threat_model>
## Trust Boundaries

| Boundary | Description |
| --- | --- |
| checked-in route content -> generated public PNGs | Public project, writing, theme, and index route text becomes share-card image content. |
| social preview target asset path -> local filesystem | `/social/generated/...` web paths become writable files under `public/social/generated/`. |
| SVG template text -> resvg renderer | Curated copy is interpolated into XML/SVG and then rasterized by a native dependency. |
| generated PNGs + manifest -> static deploy artifact | Checked-in files are copied into `.output/public` and later crawlers can request them. |
| maintainer CLI -> local environment | The generator runs on a developer or clean-builder machine but must not read secrets, make network requests, use runtime services, or add runtime endpoints. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
| --- | --- | --- | --- | --- |
| T-25-01 | Tampering | `scripts/social-previews/paths.ts` and generator cleanup | mitigate | Use Plan 25-01 path guards; CLI cleanup calls only managed PNG helpers and never fallback/icons/sitemap/robots/unrelated public paths. |
| T-25-02 | Information Disclosure | `scripts/generate-social-previews.ts` target inventory | mitigate | Consume only `socialPreviewTargets()` and run `validateSocialPreviewTargets()` before rendering, writing, cleanup, or check comparison. |
| T-25-03 | Tampering | `scripts/social-previews/template.ts` SVG interpolation | mitigate | Use escaped Plan 25-01 template output; CLI never interpolates SVG text itself. |
| T-25-04 | Repudiation | `public/social/generated/manifest.json` | mitigate | CLI writes only sorted timestamp-free manifest serialization containing `sourceFingerprint`, `byteSize`, and SHA-256 checksum fields. |
| T-25-05 | Denial of Service | generated PNG size and renderer output | mitigate | Check mode compares dimensions, byte budget, blank-image state, nonzero generated bytes, and nondeterministic rerenders before passing. |
| T-25-06 | Information Disclosure | generator/runtime environment | mitigate | CLI must not read `process.env`, call `fetch`, include remote asset URLs, use GitHub APIs, clocks, or randomness; scope guards check this. |

| T-25-08 | Spoofing | route card brand/copy | mitigate | CLI passes `socialPreviewTargets()` data to the template unchanged and adds no generic OpenLinks CTA or copied brand text. |
