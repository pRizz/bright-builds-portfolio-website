# Phase 05 - UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none for shadcn; this is a SolidStart, Tailwind 3, Mystic UI project with no `components.json` |
| Preset | not applicable |

## Phase-Specific UI Scope

| Surface | Contract |
|---------|----------|
| Existing project cards | Optional GitHub metadata may render only as compact secondary context inside existing project cards. Do not redesign cards, create a new landing page, change the hero, add a new route, or change navigation. |
| Metadata placement | Place one metadata row after authored project copy and flagship story content, before curated label chips and link rows. The row must not displace problem, approach, why-it-matters, role, status, maturity, or curated tags. |
| Metadata content | Render at most these visitor-facing facts: stars, forks, primary language, updated date, up to 3 useful GitHub topics, and true-only repository flags such as archived, fork, or template. Omit unavailable facts. |
| Homepage enrichment | A GitHub homepage URL may append a secondary `Live site` or `Live docs` link only when non-empty, non-duplicate, and not already covered by curated links. It must not replace curated `repo`, `live`, or `docs` links. |
| Empty metadata | If no GitHub metadata is available for a project, render no visitor-facing metadata row. The existing curated card remains complete. |
| Motion | No new animation, counter animation, layout animation, or pointer behavior for metadata. Inherit existing hover/focus card treatment only. Reduced-motion and coarse-pointer behavior must remain static. |
| OpenLinks | Preserve existing low-intrusion footer/about/contact/profile and metadata placement. Do not add new OpenLinks promotion, badges, hero content, or repeated nearby links in this phase. |

## Interaction Contract

| Interaction | Contract |
|-------------|----------|
| Metadata row semantics | Use textual labels inside a `dl` or accessible list with `aria-label="GitHub repository metadata"`. Do not rely on icons alone. |
| Keyboard access | Metadata facts are static text. Any enriched homepage link must use the existing `surface-link` and `text-link` focus-visible treatment and remain reachable by keyboard. |
| Mobile layout | Metadata chips must wrap with `flex-wrap`, `min-width: 0`, and `overflow-wrap: anywhere`. No fixed-width stat columns. No horizontal overflow at 320px, 390px, or desktop widths. |
| Text density | Use short labels: `Stars`, `Forks`, `Language`, `Updated`, `Archived`, `Fork`, `Template`. Dates use concise month-year or ISO-derived readable text, for example `Updated May 2026`. |
| Topics | Topic chips are secondary to curated themes and tags. Omit topics that duplicate curated labels or would push the card into crowding on mobile. |
| Verification evidence | Release verification may report metadata refresh errors in docs or command output, but visitor cards must stay calm and complete when enrichment is missing. |

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Inner chip padding, language dot gap, compact stat label gap |
| sm | 8px | Metadata chip gap, inline row gaps, compact stack gaps |
| md | 16px | Default card internal separation and metadata row top margin |
| lg | 24px | Existing card padding and section sub-block spacing |
| xl | 32px | Major grid and layout gaps when inherited from existing sections |
| 2xl | 48px | Major section breaks; do not add new Phase 5 spacing at this size |
| 3xl | 64px | Page-level spacing and anchor scroll margin; do not add new Phase 5 spacing at this size |

Exceptions: Keep existing `min-h-11` 44px interactive targets for links and focusable controls. Keep existing 6px chip radius and 8px card radius; radius values are inherited component shape, not spacing tokens.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label | 14px | 600 | 1.4 |
| Heading | 20px | 600 | 1.25 |

Use only 400 and 600 weights. GitHub metadata chips use the Label size; numeric values may use 400 but must stay at 14px.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | #050608 | Root background, page shell, static dark canvas |
| Secondary (30%) | #18181B | Project cards, metadata rows, chip surfaces, nav/footer surfaces |
| Accent (10%) | #6EE7B7 | Existing text links, tier/status pills, metadata language marker, card hover border, primary action fill |
| Destructive | #FCA5A5 | Destructive actions only; no visitor-facing destructive action exists in Phase 5 |

Accent reserved for: existing text links, existing primary action fill, focus-visible support alongside the existing cyan focus ring `#67E8F9`, tier/status pills, metadata language marker, and hover/focus borders. Do not use accent for full-card fills, all metadata values, generic decoration, a new OpenLinks treatment, or language-specific GitHub color palettes.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Open source |
| Empty state heading | No GitHub metadata yet |
| Empty state body | Curated project copy still renders. Refresh the static snapshot when public repository metadata is available. |
| Error state | GitHub metadata refresh failed. Keep the checked-in snapshot and review the sync report. |
| Destructive confirmation | None: Phase 5 adds no visitor-facing destructive action. Snapshot overwrite belongs to tooling and must require an explicit command flag, not a web UI confirmation. |

Visitor-facing project cards should normally omit the empty/error copy and simply omit unavailable metadata. The empty and error copy is for release-verification notes, docs, or a future non-visitor maintenance surface.
