# Phase 21 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | Tailwind CSS 3 with Mystic UI setup and repo-local dark-primary CSS classes; shadcn is not applicable for this SolidStart stack. |
| Preset | `withMysticUI`, Tailwind `darkMode: "selector"`, `.dark` active on the root document. |
| Component library | Mystic UI dependency plus repo-local `SiteLayout`, `ReactiveSurface`, and CSS component classes. Do not add new UI dependencies. |
| Icon library | None for Phase 21. Use text links and existing button/link classes; do not add an icon package for these collaboration surfaces. |
| Font | `Inter, ui-sans-serif, system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif`. |

Design system contract:

- Reuse `project-detail-panel`, `visual-surface`, `link-list`, `surface-link`, `chip`, `tier-pill`, `writing-related-grid`, `project-anchor-card`, and `surface-card` before adding CSS.
- New collaboration UI must be compact grouped rows or lists inside existing panels, not a marketing hero, decorative card stack, or card nested inside another card.
- Route components remain thin shells. Relationship and collaboration action decisions must come from pure helper output, not hand-filtered route-local data.
- No new animation, icon, component, registry, CMS, search, analytics, newsletter, comments, runtime fetch, or live external-link check dependency is allowed in this phase.

---

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Tight metadata and action-label gaps. |
| sm | 8px | Compact row gaps, chip gaps, grouped link spacing. |
| md | 16px | Default list gaps, panel internal stacks, theme link item spacing. |
| lg | 24px | Existing card/panel padding and collaboration panel padding. |
| xl | 32px | Detail page layout gaps and related-content group rhythm. |
| 2xl | 48px | Major mobile section breaks through existing route spacing. |
| 3xl | 64px | Desktop page separation and sticky-header scroll offsets only. |

Exceptions: interactive anchors and buttons must keep the existing `min-h-11` 44px target size. Cards and panels stay at 8px radius; chips and pills stay at 6px radius. New CSS may only add multiples of 4 unless matching these existing local radii or the 44px target.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label | 14px | 600 | 1.4 |
| Heading | 20px | 600 | 1.25 |
| Display | 36px | 600 | 1.15 |

Typography rules:

- Use only weights 400 and 600.
- Keep letter spacing normal and do not scale type with viewport width.
- Collaboration panel body copy uses body size. Action labels and small group labels use label size. Panel headings use heading size. Existing route H1s continue to use display size.
- Long theme titles, project names, writing titles, URLs, proof points, and action labels must wrap through existing `min-width: 0` and `overflow-wrap: anywhere` patterns.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#050608` with existing shell gradient through `#0d1117` and `#12100b` | Page background, dark root, main shell. |
| Secondary (30%) | `rgba(24, 24, 27, 0.84)` over `#0d1117` | Collaboration panels, related-theme panels, cards, sticky nav, visual surfaces. |
| Accent (10%) | `#6ee7b7` emerald, with `#67e8f9` cyan only for focus/hover support | Destination links, action rows, focus rings, hover borders, tier pills, small relationship labels. |
| Destructive | Not used | Phase 21 has no destructive actions. Do not introduce destructive UI. |

Accent reserved for: `Project story`, `Source`, `Live surface`, `Read note`, `Read essay`, `Contact path`, and `Explore theme` links; focus-visible rings; hover borders on existing cards/panels; `tier-pill` and chip emphasis. Do not use accent as a broad background wash, decorative orb, or generic color for every block of text.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | `View project story` |
| Empty state heading | `No collaboration paths yet` |
| Empty state body | `When reviewed project, source, live, or writing links are available for this theme, they will appear here.` |
| Error state | `No public theme here. Browse theme paths to find a public route through Peter's work.` |
| Destructive confirmation | None: Phase 21 has no destructive actions. |

Required labels:

| Surface | Required Copy |
|---------|---------------|
| Theme collaboration panel heading | `Collaboration starting points` |
| Theme collaboration angle label | `Where to start` |
| Project story action | `Project story` or `View project story`; use the shorter label in dense grouped rows and the verb label for a single primary row. |
| Source action | `Source` |
| Live action | `Live surface` |
| Writing action | `Read note` or `Read essay`, matching the writing entry kind. |
| Contact fallback action | `Contact path` |
| Project related-themes panel heading | `Related theme paths` |
| Writing related-themes section heading | `Related theme paths` |
| Theme cross-link action | `Explore theme` |

Copy rules:

- Prefer destination-specific labels. Do not use `Learn more`, `Read more`, `Click here`, or repeated ambiguous `Details` labels.
- Omit related-theme panels when no public themes reference the project or writing entry. Do not show a route-visible empty panel on project or writing detail pages.
- The theme collaboration panel may use the empty-state copy only if all helper-derived collaboration actions are absent after defensive filtering.
- Keep OpenLinks copy identity-oriented: `OpenLinks profile` or `Contact path` only when the link comes from existing profile/contact data or the `open-identity` theme's related OpenLinks project.

## Collaboration Interaction Contract

| Surface | Contract |
|---------|----------|
| Theme detail collaboration panel | Add one compact `project-detail-panel visual-surface` panel to public `/themes/{slug}` detail pages. Place it in the existing detail aside, before or near existing related project/writing panels, so it is discoverable without replacing the page intro or `Why it matters` story. |
| Panel content order | Render the theme `collaborationAngle` first under `Where to start`, then helper-derived project story actions, reviewed source/live actions from related selected projects, related writing actions, and a low-intrusion contact/profile fallback only when useful. |
| Action source | Assemble actions from `collaborationAngle`, `relatedProjectDetailPageProjectsForTheme()`, `relatedWritingEntriesForTheme()`, existing project `links`, checked-in GitHub metadata helpers when already available, and `peterProfile.links` only for fallback/contact identity. Do not introduce new external-link fields or runtime network data. |
| Action layout | Use a list or grouped rows with real anchors. Do not make entire panels or cards clickable through JavaScript handlers. Do not duplicate the full related project/writing card grid inside the panel. |
| External links | Reviewed source/live/profile links open with `target="_blank"` and `rel="noopener noreferrer"`. New visible OpenLinks links must include `rel="me noopener noreferrer"` when sourced from profile identity data. |
| Keyboard behavior | Every action is reachable by Tab, has descriptive text, and keeps the existing visible cyan focus ring. Maintain the 44px minimum target through `surface-link` or equivalent existing classes. |
| Motion | Do not add motion. Existing hover/focus transitions must remain disabled by the reduced-motion, coarse-pointer, and mobile guards in `src/styles/app.css`. |

## Cross-Link Interaction Contract

| Surface | Contract |
|---------|----------|
| Project detail pages | Add related theme links only to selected project detail pages when public themes reference that project. Place the panel inside the existing project aside after existing project actions/related writing content, so the project story remains primary. |
| Writing detail pages | Add related theme links only to public writing detail pages when public themes reference that writing entry. Place the section after the article body and after existing related projects, so the writing remains primary. |
| Cross-link data | Use pure reciprocal helpers that answer "which public themes reference this project?" and "which public themes reference this writing entry?" from `curatedThemes`. Helpers return only public theme entries, preserve theme display order, and return an empty list for unreferenced records. |
| Theme link presentation | Each related theme item shows the theme title, short summary, and an `Explore theme` link built with `themeDetailPath()`. Use existing `surface-card`, `project-anchor-card`, or compact list styling; avoid tag-cloud presentation. |
| Omission rule | Do not add related theme links to broad index cards, homepage project cards, navigation, footer, or unrelated route surfaces in this phase. |

---

## OpenLinks Identity Contract

- Preserve OpenLinks as a low-intrusion identity hub through the existing footer, contact/profile data, and metadata surfaces. The existing footer link `OpenLinks profile` already satisfies visible discoverability.
- Do not make OpenLinks the primary theme CTA, global collaboration CTA, navigation item, repeated panel footer, banner, or hero action.
- The `open-identity` theme may naturally show OpenLinks project actions because OpenLinks is a related selected project with reviewed source and live links.
- General theme collaboration panels prioritize related projects, writing, GitHub/source surfaces, and theme-specific collaboration context before any identity/contact fallback.
- If a new visible OpenLinks fallback link is unavoidable, source it from `peterProfile.links`, use the existing `OpenLinks profile` or `Contact path` copy, and include `rel="me noopener noreferrer"`.

## Route Boundary Contract

| In Scope | Out of Scope |
|----------|--------------|
| Theme collaboration starting-point panel on public theme detail pages. | Phase 22 metadata, JSON-LD, sitemap, Open Graph/Twitter tags, and social-preview behavior. |
| Reciprocal related-theme links on selected project detail and public writing detail pages. | Phase 23 release-contract labels, broad release documentation, and aggregate release evidence wording. |
| Pure helper-derived collaboration action assembly and reciprocal theme helper tests. | Search, filters, tag archives, CMS/admin, analytics, newsletter, comments, runtime content fetches, or live external-link reachability checks. |
| Focused static/component/browser checks for the new links and panels. | New source URL registries, unreviewed external links, new UI dependencies, new icon dependencies, or prominent OpenLinks promotion. |

## Verification Contract

| Check | Required Evidence |
|-------|-------------------|
| Helper behavior | Focused unit tests prove reciprocal theme helpers return public themes only, preserve display order, and return `[]` for unreferenced project or writing records. |
| Collaboration action assembly | Focused unit tests prove action labels and hrefs are derived from reviewed project links, writing entries, existing profile links, and existing helpers without runtime fetches or unreviewed URL fields. |
| Theme detail rendering | Route/component/static tests prove public theme detail pages expose `Collaboration starting points`, the theme collaboration angle, project story links, reviewed source/live links when available, and related writing links. |
| Project cross-links | Route/component/static tests prove selected project detail pages show `Related theme paths` only when public themes reference the project and link through `themeDetailPath()`. |
| Writing cross-links | Route/component/static tests prove public writing detail pages show `Related theme paths` after article/related-project content only when public themes reference the writing entry. |
| OpenLinks posture | Static or component evidence proves OpenLinks is not added as a generic primary theme CTA. Any new visible OpenLinks link uses existing profile data and `rel="me noopener noreferrer"`. |
| Dark responsive UI | Browser verification covers desktop and mobile dark rendering on at least one theme detail route plus one affected project detail and one affected writing detail route; no text overlap, horizontal overflow, or unreadable contrast. |
| Accessibility | New panels keep semantic headings, descriptive anchors, visible keyboard focus, axe-clean output, and 44px touch targets. |
| Reduced motion | Existing reduced-motion/coarse-pointer/mobile guards remain effective; no new motion behavior is introduced. |
