## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| checked-in writing data -> RSS serializer | Authored titles, summaries, dates, topics, tags, and slugs cross into XML output. |
| raw writing/topic labels -> public feed categories | Raw labels must pass through canonical topic filtering before becoming public RSS categories. |
| feed domain -> static output script | Pure XML output later becomes a checked-in public asset; domain code must not own filesystem mutation. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-33-01-01 | Tampering | `rssFeedXml()` in `src/domain/feed.ts` | mitigate | Escape every dynamic channel and item text field through `escapeXmlText()` and cover `&`, `<`, `>`, and `"` behavior in `src/domain/feed.test.ts`. |
| T-33-01-02 | Information Disclosure | `writingFeedItems()` in `src/domain/feed.ts` | mitigate | Derive from `publicWritingEntries()` and add a feed-date guard so draft, hidden, archived, and undated records are excluded before serialization. |
| T-33-01-03 | Repudiation | item GUID generation | mitigate | Set item `id` and `<guid isPermaLink="true">` to the canonical absolute writing URL; forbid timestamps, indexes, hashes, and generated asset fingerprints. |
| T-33-01-04 | Tampering | `rssDateFromIsoDate()` | mitigate | Parse only checked-in ISO date strings at UTC midnight and throw `Invalid feed date: {value}` on malformed or impossible dates. |
| T-33-01-05 | Denial of Service | Feed dependency surface | accept | RSS output is small and generated from checked-in data; no XML parser, network call, runtime endpoint, or new dependency is added. |
</threat_model>
