# Phase 33 - UI Design Contract

> Visual and interaction contract for Phase 33: writing-first static feed. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Scope

Phase 33 adds RSS feed autodiscovery metadata to the home and writing pages, plus visible low-intrusion RSS feed links on those surfaces. This phase must not redesign the page, add a subscription modal, add a new primary hero CTA, add a newsletter surface, or crowd the existing OpenLinks footer identity placement.

## Placement Contract

Home page:

- Add one visible RSS link inside the existing hero `page-intro` area, near the lead and existing `Browse projects` action.
- Style it as a secondary text affordance using existing `text-link surface-link` classes.
- Keep `Browse projects` visually primary. The RSS link must not use `primary-action`, a card, a hero heading, or a modal trigger.

Writing page:

- Add one visible RSS link inside the existing writing `page-intro`, after the lead and before `DiscoveryFilterControls`.
- Use the same `text-link surface-link` treatment as home.
- Do not place the link inside the filter surface, writing cards, footer, or OpenLinks footer row.

OpenLinks:

- Leave `SiteLayout` footer placement unchanged.
- Do not add a second OpenLinks placement while adding RSS links.
- Feed links must keep Bright Builds, projects, and writing as the primary page signals.

## Interaction Contract

- The visible RSS affordance is a normal anchor: `<a class="text-link surface-link" href="/feed.xml">RSS feed</a>`.
- Use same-origin `/feed.xml` for visible links.
- Do not use JavaScript-only interaction, clipboard behavior, subscription modal, popover, toast, custom protocol handler, newsletter form, or feed-reader picker.
- The link must be keyboard reachable, visibly focused through the existing cyan focus ring, and operable before hydration.
- The link row must flex-wrap and preserve `overflow-wrap: anywhere` behavior on narrow screens.
- Do not add new decorative motion. Hover/focus behavior may inherit existing `surface-link` transitions and reduced-motion rules.

## Metadata Contract

- Home and writing pages must each expose one RSS autodiscovery link in the document head.
- Use `rel="alternate"`, `type="application/rss+xml"`, title `Bright Builds writing feed`, and an absolute canonical href: `${peterProfile.canonicalOrigin}/feed.xml`.
- Prefer extending `RouteHead` with a small optional alternate-link surface for the writing route. The home route may use the same helper or its existing inline `HeadLink` pattern, but the rendered metadata must match writing.
- Do not add Atom, JSON Feed, topic feed, project feed, or runtime feed endpoint metadata.

## Accessibility And Verification Contract

- Touch target: RSS link must retain the existing 44px minimum interactive height.
- Contrast: RSS link text must use existing emerald/cyan link colors on dark surfaces and remain readable in dark mode.
- Focus: RSS link must show the existing `focus-visible:ring-2 focus-visible:ring-cyan-300` treatment.
- Mobile: home and writing surfaces must show the RSS link without text overlap, horizontal scrolling, or crowding the filter controls.
- Static output: verification must prove home and writing HTML contain the RSS autodiscovery link and visible `/feed.xml` link.
- Browser coverage: include desktop and mobile dark rendering, keyboard focus, contrast/readability, and text-overlap checks when existing route loops do not already cover the new link.

## Out Of Scope

- No page redesign.
- No subscription modal, newsletter, WebSub, webmentions, comments, analytics, or feed-reader picker.
- No new primary hero CTA.
- No icon dependency.
- No OpenLinks promotion changes.
- No Atom, JSON Feed, topic-specific feeds, project feeds, theme feeds, or dynamic feed endpoints.
