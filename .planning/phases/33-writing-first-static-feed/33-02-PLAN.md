<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| pure feed helper -> checked-in `public/feed.xml` | Generated XML becomes a public static asset and must drift-check exactly. |
| `public/feed.xml` -> `.output/public/feed.xml` | SolidStart copies public assets during build; static verification must inspect the built artifact. |
| route code -> generated HTML head/body | Home and writing pages expose feed autodiscovery and visible links before hydration. |
| generated static output -> release evidence | Local verification must prove only deterministic static feed output without hosted feed-reader claims. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-33-02-01 | Tampering | `scripts/generate-feed.ts` | mitigate | `--check` mode compares `public/feed.xml` to `rssFeedXml()` and throws `Feed output is out of date. Run bun run generate:feed.` without rewriting. |
| T-33-02-02 | Information Disclosure | `scripts/verify-static/feed-verifier.ts` | mitigate | Static verifier asserts built feed includes every public dated writing item and excludes non-public, undated, project, theme, subscription-product, and alternate feed-format content. |
| T-33-02-03 | Denial of Service | runtime feed/content dependency | mitigate | Keep `/feed.xml` as a copied public asset, add no runtime endpoint, and run `verify:feed` plus static/release checks in `bun run verify`. |
| T-33-02-04 | Spoofing | home/writing autodiscovery links | mitigate | Use `writingFeedMetadata().feedUrl` from `peterProfile.canonicalOrigin`, with static verification for `rel`, MIME type, title, and absolute canonical href. |
| T-33-02-05 | Repudiation | local release evidence | mitigate | Static summary names `feed XML` only after `.output/public/feed.xml` is checked; hosted feed-reader validation remains out of scope and is not claimed. |
</threat_model>
