# Phase 03 - UI Design Contract

> Visual and interaction contract for Phase 03 portfolio surfaces and SEO. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | Mystic UI theme plus repo-owned Solid components and shared Tailwind component classes |
| Icon library | none for Phase 03; use text labels for links and CTAs |
| Font | Inter, ui-sans-serif, system-ui fallback |

Notes:

- `components.json` is absent. shadcn is not part of this SolidStart/Mystic UI stack.
- Keep Tailwind `darkMode: "selector"` and `.dark` active on the root document.
- Use `src/styles/app.css` shared dark-first classes for shell, surfaces, cards, links, chips, and focus states.
- Do not introduce light-first utility classes such as `bg-white`, `bg-stone-50`, or `text-zinc-950` unless the implementation records a specific local reason near the component or plan.

---

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Tight icon/text gaps, chip internal gaps |
| sm | 8px | Compact stacks, nav item gaps, chip padding |
| md | 16px | Default text stacks, card internal rhythm |
| lg | 24px | Card padding, section heading groups, mobile section gaps |
| xl | 32px | Grid gaps, hero column gap, card group spacing |
| 2xl | 48px | Main vertical padding, route intro to content spacing |
| 3xl | 64px | Desktop section breaks and footer separation |

Exceptions:

- 1px borders and dividers.
- 2px focus rings with 2px outline offset.
- 6px radius for compact buttons/links and 8px radius for cards.
- 44px minimum touch target for mobile links, buttons, and contact cards.

---

## Typography

Use exactly these four sizes and two weights for Phase 03 UI. Do not add viewport-width font scaling or custom letter spacing.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label / meta / chip | 14px | 400 or 600 | 1.4 |
| Body | 16px | 400 | 1.5 |
| Heading / card title | 20px | 600 | 1.25 |
| Display / route h1 | 36px | 600 | 1.15 |

Contracts:

- Eyebrow text may use uppercase words but letter spacing stays `0`.
- Body paragraphs must cap line length at roughly 72 characters.
- Contact URLs and long project names must wrap with `overflow-wrap: anywhere` or equivalent.
- Do not use fake skill bars, resume-style percentage labels, or template-heavy marketing headlines.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#050608` | Page background and dark-primary shell |
| Secondary (30%) | `#18181b` | Cards, contact surfaces, nav/footer panels |
| Accent (10%) | `#6ee7b7` | Primary CTA, key inline links, selected status emphasis, identity/project highlight details |
| Destructive | `#f87171` | Destructive actions only; none are expected in Phase 03 |

Accent reserved for:

- Primary CTA: `Browse projects`.
- Text links that leave the current page or jump to major project anchors.
- Tier/status emphasis on project cards.
- OpenLinks identity link when it appears as a profile/contact/footer identity surface.
- Selection background and high-signal inline highlights.

Additional accessibility color:

- Focus ring: `#67e8f9`, 2px ring, 2px offset. This is an accessibility state, not decorative accent.
- Notice/current-focus marker: `#fcd34d` only for a thin left border or small status marker.

## Surface Contract

### Global Shell

- Header stays sticky with dark translucent surface, subtle border, and readable nav wrap on small widths.
- Skip link remains first focusable element and becomes visible on focus.
- Main content uses max width `72rem` with 20px mobile side padding and 48px vertical padding.
- Footer keeps Bright Builds as the host brand and includes one low-intrusion OpenLinks identity link.

### Home

- First content block is identity-first: Peter Ryszkiewicz / pRizz, Bright Builds, and focus areas must be visible before project cards.
- Desktop layout at 1024px and above uses a two-column hero: identity copy on the left, compact current-focus panel on the right.
- Mobile layout is one column with current-focus content below the identity intro.
- Home shows 4-6 flagship project stories from `homeProjects()`.
- The home CTA label is `Browse projects` and links to `/projects`.

### Projects

- Use `/projects#${project.slug}` stable anchors for Phase 03. Do not add per-project routes in this phase.
- Each project article has `id={project.slug}` and `scroll-margin-top: 96px` or equivalent so anchored headings are not hidden under the sticky header.
- Group visible projects in this order: Flagship, Supporting, Lab / Prototype, Archive.
- Hidden or excluded records do not render as public cards. If referenced, they appear only as a count or editorial note explaining that the portfolio is curated.
- Each flagship card shows problem, approach, role, status/maturity, why-it-matters copy, themes/tags, and useful links when data exists.
- Supporting and lab cards may be more compact, but must still show role, maturity/status, one-line copy, labels, and at least one useful link.
- Current-focus surface highlights active bets such as OpenLinks, Free The World, Win3Bitco.in / Open Bitcoin Web Miner, Open Bitcoin, and opencode-cloud when registry data is available. It is editorial, not a raw repository mirror.

### About

- About is a concise themes narrative, not a resume page.
- Required theme coverage: agentic engineering, open source, Bitcoin/decentralized systems, web tooling, and creative experiments.
- Focus-area chips may link to `/projects` anchors only when the destination is meaningful and keyboard accessible.
- Include OpenLinks once as an identity hub link if it fits the profile section; avoid repeating it near an existing footer/contact placement.

### Contact

- Contact cards render from `peterProfile.links`.
- Priority order: GitHub, OpenLinks, Bright Builds, then any future contact path.
- Contact cards are full-card links with visible label and visible URL.
- External links use `target="_blank"` plus `rel="noopener noreferrer"`; self-owned identity links include `rel="me noopener noreferrer"`.
- OpenLinks copy reads as an identity hub, not the primary portfolio CTA.

### Cards And Primitives

- Cards use `#18181b` or dark translucent surface, 1px `white/10` border, 8px radius, and 20-24px padding.
- Do not nest cards inside cards.
- Project cards must keep title, meta, body, tags, and links in a stable vertical rhythm; hover states cannot resize cards.
- Chips use 14px text, low-contrast dark fill, visible border, and no all-caps tracking.
- Primary CTA uses accent fill with dark text and 44px minimum mobile target.
- Text links are descriptive; avoid repeated `Source` when multiple links are adjacent without context. Prefer `Open source`, `Live site`, `Docs`, or project-specific labels.

## SEO And Social Preview Contract

- Metadata derives from pure TypeScript helpers in `src/domain/seo.ts` and route/project/profile data. Do not duplicate route metadata literals across route components.
- Each indexable route emits static `title`, `description`, canonical URL, Open Graph title/description/url/type, Twitter card/title/description, and image metadata before hydration.
- Add one static social preview image for Phase 03 at `/social/bright-builds-og.png`.
- Social preview image requirements: 1200x630 PNG, dark background, Peter Ryszkiewicz / pRizz, Bright Builds, and the AI/Bitcoin/open-systems/developer-tooling focus. Keep text large enough to read at small preview sizes.
- Add `og:image`, `og:image:width`, `og:image:height`, `og:image:alt`, `twitter:image`, and `twitter:image:alt` from the same helper data.
- Add favicon/touch assets: `/favicon.svg`, `/icon-192.png`, and `/apple-touch-icon.png`.
- Add or maintain `sitemap.xml` and `robots.txt` from `siteRoutes` / `prerenderRoutes`.
- Emit JSON-LD `Person` for Peter with `sameAs` including GitHub and OpenLinks.
- Emit project structured data as an `ItemList` for `/projects` when enough registry data exists. Per-project OG images and per-project routes are deferred.

## Accessibility And Interaction Contract

- Default rendering is dark mode. Contrast target is WCAG AA: 4.5:1 for body text and 3:1 for large display text and non-text UI boundaries.
- Every interactive element has a visible focus state using the focus ring color defined above.
- No important content is hover-only. Hover may add emphasis but must not reveal exclusive links, labels, or copy.
- Touch targets are at least 44px high on mobile.
- Keyboard order follows visual order: skip link, brand, nav, main content, project cards, footer.
- Anchor links must land on meaningful headings.
- External links must be distinguishable by visible label or surrounding copy, not icon-only treatment.
- Contact URLs and long project names must wrap without overflow on 320px width.
- Use semantic headings in order: one `h1` per route, grouped project sections as `h2`, project card titles as `h3` where nested under a section.
- Images and social assets have meaningful alt text in metadata or markup when rendered on-page.

---

## Reduced-Motion Contract

- Phase 03 does not add reactive physics, scroll-linked animation, canvas animation, or motion-heavy visual effects.
- Existing CSS transitions stay at or below 120ms and only affect color, background, border, opacity, or transform.
- Add `prefers-reduced-motion: reduce` handling that disables non-essential transitions and any smooth scrolling introduced for anchors.
- Social preview and icon assets are static.
- Phase 04 owns advanced Bright Builds motion and physics behavior.

## Verification Expectations

Implementation plans for this phase must include these checks:

- `bun run format:check`
- `bun run check`
- `bun run typecheck`
- `bun run test`
- `bun run build`
- `bun run verify:static`
- `bun run verify`

Static verification must prove:

- Generated HTML exists for `/`, `/about`, `/projects`, and `/contact`.
- Route-specific title, description, canonical, Open Graph, Twitter, JSON-LD, and meaningful body content exist before hydration.
- `/projects` contains stable anchors for visible project cards.
- Sitemap, robots, favicon/touch/icon assets, and `/social/bright-builds-og.png` exist and are referenced by metadata.
- OpenLinks appears as a visible low-intrusion identity link and in `Person.sameAs` metadata.
- Placeholder/template residue, fake case studies, and stale standalone repo URLs remain absent.

Visual verification must cover:

- Desktop dark rendering at 1440x900.
- Mobile dark rendering at 390x844 and 320px minimum width.
- No overlapping text, clipped contact URLs, horizontal scroll, or card layout jumps.
- Keyboard focus through nav, home CTA, project anchors, contact cards, and footer links.
- Reduced-motion mode keeps the site usable and disables non-essential motion.
