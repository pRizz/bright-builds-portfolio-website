<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| public assets -> crawlers/social clients | Static files and metadata references are consumed by clients outside the app runtime. |
| build output -> verifier | The verifier trusts generated files to prove pre-hydration behavior. |
| source tree -> static site | Source code must not introduce browser GitHub API/token mechanisms into the public bundle. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-03-01 | Tampering | `public/sitemap.xml` and `public/robots.txt` | mitigate | Generate from `sitemapXml()` and `robotsTxt()` and have `verify-static` compare output content exactly to helper output. |
| T-03-03-02 | Tampering | icon and social preview asset references | mitigate | Verify public files exist in `.output/public`, check PNG dimensions from IHDR bytes, and assert `og:image`/`twitter:image` reference `/social/bright-builds-og.png`. |
| T-03-03-03 | Information Disclosure | production source and static output | mitigate | Keep `verify:no-github-runtime` in the aggregate gate and add static-output forbidden checks for GitHub API endpoints and token names. |
| T-03-03-04 | Denial of Service | static verification script | mitigate | Keep verifier filesystem-only, dependency-free, and scoped to generated route HTML/assets so `bun run verify` remains a local deterministic gate. |
| T-03-03-05 | Spoofing | canonical/social metadata | mitigate | Static verifier compares route metadata against `metadataForRoute(routeByPath(route))`, which derives from the canonical profile origin. |
</threat_model>
